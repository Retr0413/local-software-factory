# 検証と情報の蓄積

## 受入条件

Issue に対する作業の前に、目的、対象範囲、受入条件、想定する検証、必要な証跡を整理する。仕様が不明な場合は調査し、判断できない点を明示する。

## 検証

実装担当がテストを行い、検証担当が候補コミットの受入条件、実際の操作、文書に記載された使い方を確認する。認証・権限、外部入力、依存関係への影響に応じて、既存のテストや監査を用いてセキュリティを確認する。統括はコードレビューに `my-walden-review` を用い、QA やセキュリティの確認結果を照合する。

## 記録する情報

| 項目 | 例 |
| --- | --- |
| タスク | リポジトリ、Issue ID またはローカルタスク ID、目的、受入条件、関連 PR |
| 実行 | 担当、CLI 種別、Herdr のセッションと worktree、対象コミット、状態 |
| 検証 | 実行コマンド、結果、対象コミット、環境、未検証の事項 |
| 証跡 | ログ、差分、スクリーンショット、操作手順の参照 |
| 改善情報 | 失敗や停止の理由、レビュー指摘、人間の修正、手戻り、実行時間 |

作業中に得た情報を記録し、完了・失敗・中断の場合も後から参照できるようにする。記録には機密情報が含まれ得るため、保存先や共有範囲、保持期間は運用に合わせて決める。

## 改善について

今回の範囲は、改善につながる情報を蓄積し、必要に応じて人が参照できる状態までとする。収集した記録の自動分析、Skill・Hook の自動変更、改善 PR の作成と採用は今後の設計対象とする。
