# セキュリティ確認

- ベースと候補の差分から、認証・認可、外部入力、データの出入り、依存関係、設定のうち変更が影響する範囲を確認する。どの利用者やサービスが、どのデータや操作にアクセスできるべきかを前提として記す。
- 既存のテスト、静的チェック、依存関係の監査、公式のアドバイザリを使って確認する。依存関係の指摘では、対象バージョンとロックファイルを照合する。認証・認可の場合は、許可された操作と拒否されるべき操作のテスト結果を確認する。
- 結果は候補 SHA、該当箇所、影響、確認できた根拠、修正の方向性、未確認事項を添えて統括に返す。Walden レビューに渡せるよう、根拠と推測を区別する。検証は対象プロジェクトのコードと許可されたテスト環境に限定する。

## 変更点に応じた確認例

権限の変更では、既存のテストユーザーとテストデータで許可される役割・対象を表にし、許可ケースと拒否ケースを既存の認可テストに対応づける。拒否ケースは応答に加えて、更新が発生していないことも仕様に応じて確認する。

依存関係の更新では manifest と lockfile の差分を照合し、直接依存と一緒に変わった間接依存を区別する。監査結果が出たら、対象パッケージ、解決済みバージョン、公式情報の影響範囲を並べる。依存グラフや対象バージョンを確認できない指摘は、確定事項と分けて返す。
