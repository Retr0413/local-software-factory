# バージョン・環境差から変更箇所を絞る

報告時のバージョン、lockfile で解決されたバージョン、実行環境が同じかを調べる。移行ガイドの変更点から、旧 API を呼ぶ箇所・互換ラッパー・利用者向けの設定例をたどり、「名前の置換で済む箇所」「既定値や戻り値の意味が変わる箇所」に分ける。報告時の版が不明なら比較の前提として明記する。履歴上で最初に触れたコミットは原因の候補。良い版と悪い版で同じ入力を実行して挙動を区別できるかは QA に引き継ぐ。

比較結果を「環境／解決済みの版／該当する呼び出し箇所／観測または未確認」で返す。環境差を取り除いても症状が説明できなければ、次に切り分けたい入力や境界を一つ示す。

## 判断例

新しいライブラリの既定値が変わったケースでは、引数省略・値を明示・旧設定ファイル経由の3経路をたどる。古い環境の構築に失敗した場合は、その版の動作を未確認として QA に渡す。
