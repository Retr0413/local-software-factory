# 改善に使える観測を記す

`observations` に停止や手戻りの原因、再発した指摘、起動手順の不足などを、発生した工程と根拠とともに残す。推測は推測と分かるように書く。

改善材料には、どの工程で何が繰り返されたかと、その根拠を残す。「CI が不安定」だけでは原因を追えない。「同じ候補で初回は依存取得中にタイムアウト、再実行では取得成功。両実行 URL を記録」のように観測できた差を書く。

比較に使う数値は、単位・対象期間・出典と一緒に保存する。同じ候補を再試行した記録は候補 SHA と実行 ID で区別する。たとえば初回失敗と再試行成功は2実行・1候補。ログが取得できず再試行回数が不明な場合は「不明」とし、観測できたゼロ回と区別する。

## 判断例

例えば2件の Issue のうち片方だけログを取得できた場合、再試行率の分母を2件として算出すると過小評価になる。観測できた件数とログ不足の件数を記し、後から集計できるよう実行 ID を添える。
