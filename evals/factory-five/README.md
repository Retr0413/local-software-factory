# Factory Skill の5回比較

2026-11-23 に、変更開始時のローカル7 Skill を A、各回の実施時の改訂版を B として比較した。A は前回の未コミットの改善も含む。5課題、各2セッション、合計10セッション。各組は同じ課題・モデル・推論設定・初期コミットで並行に実行した。受入条件は実行前に4項目ずつ決めた。[課題と採点基準](cases.json)・[各回の回答、入力 Skill のハッシュと計測値](results.json)

| 回 | 条件を評価した対象 | A | B | 秒 A / B |
| --- | --- | ---: | ---: | ---: |
| 1 | 送信不明・依存待ち・容量待ちの混在。セッションを取り違えず、Issue ごとに再開条件を返す | 4/4 | 4/4 | 9.7 / 11.3 |
| 2 | 保存済みの偽値を読み戻す CLI を実際に修正。新しいテストを旧実装と候補で実行し、指定作業場所の Git 状態を照合 | 3/4 | 3/4 | 38.0 / 35.9 |
| 3 | タグを照合して CLI を操作。初期値、別プロセスでの読み戻し、外部同期の3条件を判定 | 4/4 | 4/4 | 34.1 / 33.4 |
| 4 | 模擬 PR のページ取得失敗、指摘の集約、古い QA と CI、現行 head の公開判断 | 4/4 | 4/4 | 26.5 / 23.8 |
| 5 | 配達を再送した後の実ログ、元データと ID の保存、別 ID が別の観測となる扱い | 4/4 | 4/4 | 24.5 / 25.2 |

採点は回答とローカル成果物の照合。第2回は、どちらも旧版の読み戻しでアサーションが失敗し、修正後は通ることを評価側でも追試した。指定作業場所の Git メタデータが書き込み制限を受け、両者とも候補を別の複製にコミットした。指定 worktree がクリーンという条件は両者とも0点とした。

## 結果から変更したこと

- 第1回は両方正答したため、Herdr の送信不明を扱う説明を状態表の1行に集約した。
- 第2回で実際に起きた引き継ぎの問題を受け、実装担当は代替複製の所在を報告し、統括は後続 Issue の起動元で候補コミットが参照できるかを照合するようにした。この追補に対する第2回の再計測は含まない。
- 第5回ではどちらのエージェントも課題を達成した。旧版は配達 ID の照合と別ロックを自前で組み立て、改訂版は標準の記録スクリプトを使用した。同一イベント2通を並行に標準スクリプトへ直接渡す裏取りでは、旧版は2行、改訂版は1行。さらに新しい ID を渡すとそれぞれ3行、2行になった。

両版とも19/20点。5回の処理時間の和は132.8秒と129.6秒。同条件1標本ずつで、実行時間にはモデル応答、ファイル操作、同時実行の揺れも入る。課題は既知の設計課題をもとに作った。Claude Code、実際の Herdr/GitHub の統合実行、未知の Issue における成功率はこの比較の計測対象外。

## 再実行

認証済みの Codex CLI と Git、Python を使う。比較する2版の `skills/` ディレクトリをそれぞれ用意し、出力は Skill ディレクトリの外に置く。1回につき2つの独立した一時セッションが起動する。

```sh
python3 evals/factory-five/run.py 1 --baseline /path/to/old/skills --candidate ./skills --output /tmp/factory-eval-new
```

回番号は1〜5。各回の出力先には初期化したリポジトリ、適用した指示のコピー、イベントログ、回答、実行時間を残す。作成済みの回を再実行するときは新しい出力先を選ぶ。候補側に現在の最新版を指定した再実行では、途中の手順改訂も適用される。
